This is RAI, Robot Agent Interface. An agent gets a robot arm. Then it loses the map.

In Build, WebMCP gives the agent fifteen authoring tools. It loads Arm 101: a synthetic serial arm with a camera, gripper, practice can, and visible goal. Every change appears in the same three-dimensional scene the person sees.

Then the agent starts a blind trial. The can moves to an unknown reachable placement. All nineteen tools remain discoverable, but only four still work: observe the camera, read arm telemetry, send joint and gripper outputs, or end the trial.

Here is the boundary working. A Build-only scene request returns PHASE LOCKED and no hidden state. The operating agent gets normalized image-space detections, joint positions, limits, and gripper state—no object IDs, world coordinates, distances, inverse kinematics, or success oracle.

The first camera observation sees the can nearly upright, with a long-axis angle of 96.393 degrees. The agent changes joint targets, closes the gripper, rotates the wrist, and releases.

It does not get to call “tip can.” The centered final frame is ambiguous, so the agent moves to a thirty-five-degree side view. That retry measures 41.017 degrees: visibly tipped in the image.

The person sees the whole attempt as Observe, Sense, Act, Retry, and Result. The final interface reports the can released at 79.6 degrees and the goal Done. The operating agent never received that human-facing result as a shortcut.

RAI turns agent control into something a person can inspect, not just an answer from a hidden backend.

RAI is a deterministic kinematic research sandbox—not a full physics engine or physical-robot claim. It does not prove force, friction, gravity, torque, or sim-to-real transfer.
